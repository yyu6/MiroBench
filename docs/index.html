§ 01 · OVERVIEW

Real discussions are structurally and stylistically different from what LLMs produce.

MiroBench scores generated discussion threads on the dimensions where LLMs reliably fail — comment-tree branching, neutral-tone production, lexical diversity, length variance, and stance disagreement — and computes statistical distance to a held-out distribution of real human threads.

Of the 57 raw metrics computed by our nine scoring families, only 12 truly discriminate between real and synthetic. The rest are either redundant or near-zero on both real and generated data (toxicity sub-variants, for example). We report all 57 but recommend the 12.

01 — SCORE
Run 9 scorer families across your generated threads
A single CLI command. Outputs thread_scores.csv with all 57 metrics.
02 — COMPARE
Statistical comparison against real reference data
MWU, KS, Cliff's δ, Wasserstein distance, empirical fail-rate.
03 — CALIBRATE
LLM-driven iterative prompt overlay tuning
A reasoner agent reads metric gaps and proposes overlay edits.

§ 03 · METRICS

The 12 metrics that consistently distinguish LLM from human discussion.

Of the 57 raw metrics computed by MiroBench's nine scoring families, these twelve fail significance tests across every (model × domain) cell we tested. They capture the real structural gap between synthetic and real Reddit.

FAMILY 01

Diversity

3 metrics
self_bleu_4
4-gram surface repetition across comments.
semantic_mean_cosine
Sentence-embedding similarity between comments.
self_bertscore_mean_f1
Token-level semantic similarity (BERTScore).
FAMILY 02

Tone & civility

4 metrics
hard_disagree_rate
Strong disagreement fraction.
polite_rate
Over-politeness signal.
impolite_rate
Sanitization signal — LLMs trend to zero.
neutral_rate
Tone variation; LLMs almost never neutral.
FAMILY 03

Structure

3 metrics
length_cv
Comment-length variation.
avg_depth
Reply nesting depth.
structural_virality
Tree branching shape (Wiener index).
FAMILY 04

Content

2 metrics
mean_story_probability
Narrative content density.
emotion_entropy
Diversity of emotion labels per thread.

Bar fill ≈ average relative gap (real ↔ generated) across the four models tested. Higher = more discriminative for benchmarking. Avg-depth and structural-virality saturate because every LLM tested produces avg_depth = 1.0 and virality = 0.

§ 04 · QUICK START

Three commands from install to a per-metric statistical comparison.

1 Install
shell 
# clone + install editable
git clone https://github.com/yyu6/MiroBench.git
cd MiroBench
pip install -e .
2 Score your generated threads
shell 
# each thread = a directory containing discussion.json
mirobench score my_generated_threads/ --device cpu

# → my_generated_threads/thread_scores.csv  (57 metrics × N threads)
3 Compare against real Reddit
shell 
mirobench compare my_generated_threads/thread_scores.csv \
    --domains credit_cards cameras \
    --core-only \
    --model-name "my-model"

# → mirobench_comparison.csv  (MWU / KS / Cliff's δ / Wasserstein)
CLI Reference
  • mirobench domains
  • mirobench score <dir>
  • mirobench compare <csv>
Devices
  • --device cpu
  • --device cuda
  • --device mps
Thread format

See examples/example_thread.json.

§ 05 · CALIBRATION

An LLM reasoner that reads your metric gaps and rewrites your prompt overlay.

The calibration system runs a three-phase pipeline. A reasoner agent observes per-metric statistical gaps, proposes overlay edits to the generation prompt, runs candidate simulations, and selects the configuration with the lowest distance to real data.

0
Baseline

Score vanilla simulation against real data

Run the uncalibrated generator, score on all 57 metrics, compute MWU / KS / Wasserstein against the real-test split. This establishes the before point.

1
Iterative loop

Reasoner proposes overlay edits per iteration

For each of ~12 iterations: read the worst-failing metrics, generate 5 candidate overlay diffs, run small candidate simulations, score, rank, and keep the best. Candidates that improve the validation split are merged into the running overlay.

2
Final

Re-run with the best overlay; emit comparison

Generate N threads with the final overlay, score them, and produce a per-metric before vs after comparison report with effect-size reductions and improvement deltas.

CLI
shell 
python -m calibration \
    --real-train-csv mirobench/data/credit_cards/reference_scores/thread_scores_train.csv \
    --real-val-csv   mirobench/data/credit_cards/reference_scores/thread_scores_val.csv \
    --real-test-csv  mirobench/data/credit_cards/reference_scores/thread_scores_test.csv \
    --few-shot-dir   path/to/real_discussions/ \
    --products-json  path/to/products.json \
    --output-dir     calibration_runs/credit_cards \
    --calibration-model gpt-4o-mini \
    --iterations 12 --candidates 5 \
    --final-sim-runs 9 --min-sim-threads 50
